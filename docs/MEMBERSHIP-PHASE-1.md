# عضويات Deep Documentary — المرحلة الأولى

## نتيجة الفحص وحدود هذه المرحلة

الموقع HTML/CSS/JavaScript ثابت، دون عملية بناء أو خادم عضويات. النطاق في CNAME هو deepdocumentary.com. التغييرات إضافية؛ لا نعدل المقالات أو الألعاب أو نظام تقدم القراءة المحلي، ولا ننقل نتائج الألعاب القديمة إلى نقاط موثوقة.

المنفذ: ترحيل قاعدة بيانات بمعاملات وعزل RLS، صفحة account.html عربية مستقلة، تسجيل الاسم والبريد وكلمة المرور، Google، تأكيد البريد واستعادة كلمة المرور، تعديل الاسم، عرض وحذف المفضلة وسجل القراءة، عرض النقاط والشارات، وإحصاءات إدارة محدودة يتحقق الخادم من صلاحيتها. كل ذلك يحتاج Supabase للتشغيل. المفتاح الافتراضي مغلق؛ لا تحمل الصفحة SDK ولا تتصل بالخدمة قبل تفعيل الإعدادات العامة. لا توجد روابط عضوية في الموقع المنشور حاليًا.

المؤجل عمدًا: أزرار حفظ المقال وتسجيل القراءة السحابي، إصدار النقاط والشارات تلقائيًا، اشتراك Brevo وتأكيده وإلغاؤه ومزامنته، ولوحة إدارة تفصيلية للمشتركين. جداولها أساس وليست خدمات مفعلة. لا يجمع التسجيل موافقة بريدية ولا يدعي تسجيل اشتراك. حد عرض القوائم 100 عنصر والنقاط 1000 سجل؛ يلزم ترقيم صفحات وتجميع خادمي قبل تجاوزها.

## 1. أنشئ Supabase بنفسك

1. أنشئ مشروعًا من https://supabase.com/dashboard واختر منطقة مناسبة واحفظ كلمة مرور قاعدة البيانات لديك.
2. في SQL Editor شغّل `supabase/migrations/202611050001_membership.sql` مرة واحدة على مشروع جديد/بيئة اختبار أولًا. الترحيل ليس لإعادة التشغيل. إن وجد نظام عضويات سابق، راجع التعارضات قبل التطبيق. لم يُطبق أي ترحيل على خدمة حقيقية بهذه المهمة.
3. Authentication: فعّل Email وكلمات المرور وتأكيد البريد، واضبط الحد الأدنى لكلمة المرور على 12. اضبط SMTP للإطلاق واختبر وصول التأكيد والاستعادة وحدود الإرسال في حسابك.
4. URL Configuration: Site URL = `https://deepdocumentary.com`؛ أضف تحديدًا `https://deepdocumentary.com/account.html` و`https://deepdocumentary.com/account.html?mode=recovery` إلى Redirect URLs. أضف عناوين بيئة الاختبار الدقيقة عند الحاجة، دون wildcard للإنتاج.
5. لتسجيل Google: أنشئ OAuth client من نوع Web في Google Cloud وأكمل شاشة الموافقة. ضع عنوان callback الذي يعرضه Supabase (عادة `https://PROJECT.supabase.co/auth/v1/callback`) في Authorized redirect URIs لدى Google. أدخل Client ID وClient Secret داخل إعداد Google في Supabase فقط؛ لا تضع Secret في المستودع أو المحادثة.
6. أرسل للمطور **Project URL وPublishable key الذي يبدأ بـ sb_publishable_ فقط**. لا ترسل كلمة مرور قاعدة البيانات أو service_role أو sb_secret أو Google Client Secret. المفتاح العام مسموح في المتصفح لكن الحماية تعتمد على RLS.
7. بعد الاختبار، ضع القيمتين العامتين في `assets/member-config.js` واجعل `enabled: true` على فرع المعاينة أولًا. الصفحة تحمل نسخة SDK محددة من jsDelivr عند التفعيل فقط؛ راجع سياسة السماح بالمصادر/CSP عند اعتمادها. لا توجد مفاتيح حقيقية في النسخة الحالية.

## 2. الإدارة والبيانات

أنشئ حساب المسؤول وأكد بريده. من SQL Editor فقط أضف UUID الصحيح من Authentication Users:

```sql
insert into public.member_admins(user_id) values ('ADMIN_USER_UUID');
```

لا تعتمد الصلاحية على raw_user_meta_data القابلة للتعديل. الإحصاءات RPC محمية، ولا تعرض قائمة بريد الأعضاء للمتصفح. الإدارة التفصيلية لاحقًا تحتاج وظائف خادم تتحقق من العضوية الإدارية لكل طلب.

member_awards وmember_newsletter لا تقبل كتابة الأعضاء. reading.progress إفادة من القارئ وليست إثبات قراءة ولا تمنح نقاطًا. عند نشر مقال جديد يلزم إضافته إلى member_articles قبل ربطه بالمفضلة. حذف المستخدم من Auth يحذف بيانات العضوية المرتبطة؛ حذف جهة اتصال Brevo لاحقًا يتطلب معالجة مستقلة.

## 3. أنشئ Brevo لاحقًا دون مشاركة المفتاح

أنشئ حسابًا على https://app.brevo.com ثم وثق المرسل والنطاق، وأنشئ قائمة وقالب تأكيد اشتراك double opt-in وصفحة عودة عامة. أرسل **List ID وTemplate ID ورابط العودة العام** فقط؛ ليست مفاتيح سرية. خزّن Brevo API key في إعدادات أسرار Supabase Edge Functions بنفسك.

المرحلة التالية ستضيف وظيفة خادم للتحقق من جلسة العضو وموافقته الصريحة غير المحددة مسبقًا، وحدود الطلبات، واستدعاء Brevo DOI، ومزامنة التأكيد وإلغاء الاشتراك عبر أحداث موثقة مع منع التكرار. لا تتحول pending إلى subscribed بمجرد إرسال الطلب. يجب أن تتضمن الرسائل رابط إلغاء الاشتراك وأن يتزامن الحظر مع Brevo. لا تُنشأ جهة اتصال ولا تُرسل رسالة في هذه المرحلة. راجع سياسة الخصوصية لتصف الخدمات والمعالجة فعليًا قبل تفعيلها.

## الاختبار والتدرج

هذه الأدوات للتحقق فقط؛ الموقع يظل ثابتًا دون build:

```sh
npm install --ignore-scripts
npm run test:membership
npx playwright install chromium
npm run test:browser
python scripts/check_local_assets.py
python scripts/check_shared_footer.py
```

اختبارات PostgreSQL محلية عبر PGlite تستعمل auth.uid وأدوارًا تحاكي Supabase؛ لا تختبر خدمة Auth الحقيقية. قبل إطلاق العضويات اختبر بحسابين في مشروع Supabase تجريبي: العزل ومحاولات تعديل النقاط والإدارة، البريد المؤكد، Google وقيم الاسم، الاستعادة والرابط المنتهي، الخروج وتجديد الجلسة. اختبر جوالًا وكمبيوتر واتصالًا ضعيفًا. لا تستخدم الموقع لجمع حسابات حقيقية قبل استكمال هذه القائمة وتحديث الخصوصية.

الطرح: مراجعة هذا الفرع، مشروع اختبار وإعدادات عامة، اختبارات الخدمات الحقيقية، ثم رابط العضوية وأزرار المقالات على دفعة لاحقة. الرجوع الفوري للواجهة بتغيير enabled إلى false وإزالة رابطها إن أضيف؛ يوقف عمل الصفحة ولا يحذف البيانات أو يلغي الجلسات المخزنة. حذف الجداول ليس خطوة رجوع تلقائية؛ خذ نسخة بيانات قبل أي حذف.
